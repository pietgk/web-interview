export const Tokens = ({ theme }) => {
  const flatten = (value, path = []) =>
    typeof value === 'object' && value !== null
      ? Object.entries(value).flatMap(([key, child]) => flatten(child, [...path, key]))
      : [[path.join('.'), value]]

  return flatten(theme.todos).map(([path, value]) => (
    <Row key={path}>
      <Name>theme.todos.{path}</Name>
      <Value>{String(value)}</Value>
    </Row>
  ))
}

# Design tokens

Every value on this page is read from the theme object at render time. Nothing here is
transcribed, so this page cannot drift from what the app actually uses - if a token changes,
this page changes with it.

The rule the codebase follows: **anything under `theme.todos` is a decision we made. Everything
else is a decision MUI made for us.** When you need a value that is not here, add a named token
rather than a literal at the call site - see
[the semantic constants standard](https://github.com/pietgk/web-interview/blob/master/docs/semantic-constants.md).

## Our tokens

<Tokens theme={lightTheme} />

Three of these mirror values MUI owns but does not export: `control.height`,
`control.borderOpacity` and `control.focusBorderWidth`. The completion box is not an input, so it
cannot inherit them - it copies them to sit on the same baseline as the fields beside it. The
`TodoItem` story **Controls share one height** is the gate that fails when MUI moves and the copy
goes stale.
