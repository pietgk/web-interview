# Whiteboards in docs

`npm run whiteboard` turns a `.excalidraw` scene into a self-contained HTML page and opens it. The
page is a real Excalidraw canvas rather than a picture of one, so a drawing committed to the repo
stays pannable, zoomable, and editable instead of going stale as a flat export.

```bash
npm run whiteboard                              # docs/architecture.excalidraw
npm run whiteboard docs/your-board.excalidraw   # writes docs/your-board.html beside it
npm run whiteboard docs/your-board.excalidraw --no-open
```

this tool is born to get a generated excalidraw (create by claude opus using code (see generate-architecture-board.mjs)) 
inside our documentation.
this way we can in the future generate more excalidraw drawing for documentation in a more expressive way than mermaid diagrams.
Claude opus is able to fix its own slop from the rendered output so this seems to become a useful way to document stuff.

## Adding a drawing

Drop a `.excalidraw` file in `docs/`, run the command against it, and commit both files. Link the
`.html` from whatever doc the drawing belongs to.

The page title comes from the scene's own `appState.name`, so name the drawing in Excalidraw
(**File → Rename**) rather than passing a title on the command line. One source, no second copy in
a build script.

## How it works, and why it is shaped this way

**One file, no server.** The scene JSON is inlined into the HTML rather than fetched, so the page
opens by double-click over `file://` with no dev server and no CORS. That is what makes it
committable and linkable like any other doc.

**Read first, edit second.** The board opens in view mode with an **Edit** toggle in the header. A
doc drawing is read far more often than it is changed, and view mode keeps the tool palette off the
drawing. Toggling preserves scroll, zoom, and any edits.

**Fits on open.** Excalidraw's `initialData.scrollToContent` only centres the drawing at 100%, so
the page fits to content through the imperative API one frame after mount - the callback fires
before the canvas is laid out, and fitting to a zero-size viewport is a no-op.

**Excalidraw comes from a CDN**, pinned by version in `scripts/whiteboard-html.mjs` so a release
cannot silently change what a committed doc renders. This is the one network dependency. Without
network the page shows its static fallback and says so, rather than presenting an empty canvas.

## Saving changes back

Edits in the page live in the browser only. To keep them, use Excalidraw's **File → Save to...** over
the `.excalidraw` file, then re-run the command to rebuild the HTML.

`docs/architecture.excalidraw` is the exception: it is generated by
`scripts/generate-architecture-board.mjs` from code, so edit the generator and re-run it. Editing
that scene by hand loses the change on the next generate. The generator writes the `.excalidraw`,
the `.svg` used in the README, and the `.html` through the same renderer this command uses, so both
paths produce identical output.

## Where the pieces live

| Piece | File |
| --- | --- |
| CLI: resolve a scene, write the page, open it | `scripts/whiteboard.mjs` |
| The page itself: HTML, CDN wiring, fallback | `scripts/whiteboard-html.mjs` |
| Generator for the architecture board | `scripts/generate-architecture-board.mjs` |
