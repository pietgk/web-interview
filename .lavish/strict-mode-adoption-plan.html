Recommended

Project-gated strict adoption

Set strict: true in each leaf config only when that entire project is clean. This creates a durable ratchet with a clear owner and an independently verifiable exit condition.

  • No temporary weakening after a project passes.
  • Production and tests become strict together.
  • The final base-config flip is mechanical.
Not preferred

Flag-by-flag adoption

Enabling strictNullChecks, then noImplicitAny, then the remaining flags across every project appears incremental, but it creates a long-lived configuration matrix and mixes ownership between four codebases.

  • noImplicitAny already accounts for nearly all remaining work.
  • Several strict flags produce zero diagnostics today.
  • Project gates give a clearer definition of done.

Final configuration ratchet

Each phase temporarily opts its leaf project into strict mode. After the fourth gate, move the setting to the shared base and remove redundant leaf overrides, including the current shared-only strictNullChecks.

// During a project phase
{
  "extends": "../tsconfig.base.json",
  "compilerOptions": {
    "strict": true
  }
}

// Final repository state
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "strict": true
  }
}

Typing strategy by boundary

Domain data

Import Todo, TodoList, Transaction, actor, snapshot, and storage contracts from @web-interview/todos/types. Do not duplicate domain shapes in backend or frontend.

Framework edges

Use framework-owned types for React children/events, Playwright fixtures, Express handlers, CORS callbacks, Node buffers, and IndexedDB primitives. Keep them at the adapter edge.

Unknown data

Caught errors, HTTP JSON, environment values, journal JSON, and IndexedDB records remain unknown until validated or narrowed. A cast alone is not proof of a runtime contract.

Important migration rule

Do not solve strictness by weakening the contracts just created

No blanket @ts-ignore, broad any, or type assertions around whole objects. Small assertions are acceptable only after a runtime invariant has been checked. If an IndexedDB or JSON value cannot be proven valid, add a parser or guard and define its fallback behavior.

Final gateRun npm run typecheck, npm test, npm run lint, the frontend production build, and npm run test:e2e.

Risks to watch

  • False confidence from casts: especially at IndexedDB and caught-error boundaries.
  • Over-wide UI events: an imprecise event shape will push unions and optional fields through every component.
  • Test double drift: mocks should model the subset under test without pretending to implement impossible states.
  • Inferred null-only state: React refs and state need intentional union types at initialization.
  • Generated declaration drift: shared source changes must keep emitted declarations and consumer tests green.
