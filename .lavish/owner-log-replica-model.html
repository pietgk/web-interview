What each word means in the picture

party

Owner

A human, language model, or system accountable for one Log. Decides what becomes fact through commands. Never a box in the mechanism, only a name on the invariants.

facts

Log

The append-only journal and its epoch. The identity of everything below it. One Owner, one Log. There is no word for "the whole system" because the Log is it.

facts

Replica

Any process holding the Log's compacted set and a cursor: a browser tab, a phone, an agent in-process. Only mutation is apply. Only Replicas of a Log write to that Log.

derived

Read Model

A typed view derived from a Replica. Rebuildable from the Log, never a source of facts. Includes prose for a model (context projection) and search indexes.

derived

Read Model Engine

What hosts a Read Model and answers its questions: the in-memory fold, SQLite, a vector index. Its native query surface is the Read Model's interface.

crossing

Message

Sent by a Replica of one Log, received by a Replica of another. Input, not a write. May carry entity ids or content addresses as plain values. The receiving Owner's command decides what becomes fact.

The invariants the picture is supposed to make obvious

  1. One Owner, one Log, one epoch. Every write in a Log is that Owner's intent, which is why last-write-wins is "my last intent" and needs no conflict path.
  2. Only Replicas of a Log write to that Log. Nothing from Log B can reach Log A except as a Message that A's Owner turns into a command.
  3. Facts on the left, derived on the right, one arrow between them. A Replica is facts. A Read Model is derived. There is no Replica Engine, because a Replica is its own map. The reference implementation's DatomStore fuses a Replica with one in-memory engine; that is the seam an Owner splits when adding a second engine.
  4. Owner is not on the wire. Messages travel between Replicas. Owners only decide.

Things to check against your own picture

Q1. Does "no word for the whole system" hold, or do you still want a name for "Log A and everything derived from it"?
Q2. Replica A3 is an agent that both holds facts and sends a Message. Is it right that the agent is a Replica, not a fourth kind of thing?
Q3. Bob's agent is the Owner of Log B and also runs inside Replica B1. Does Owner-as-party still read cleanly when the party is software living in its own Replica?
Q4. Is the Message arrow from Replica to Replica the right picture, or should it be Log to Log (delivered through Replicas)?
