Current versus target evidence

Current

  • Whole-number thresholds leave rounding headroom.
  • Improved files can leave stale floors behind.
  • Ignored HTML has no source revision or dirty state.
  • Directory rows look recursive but count direct files.
  • CI retains Lighthouse and discards coverage detail.

Target

  • Exact per-file {covered,total} baseline.
  • Every change requires an explicit reviewed ratchet.
  • Canonical report names revision, state, time, and scope.
  • Recursive rollups are visibly labelled as recursive.
  • Coverage and Lighthouse both remain available for 14 days.

Risks and containment

Instrumentation movement

An unexplained tuple change becomes visible and blocks until reviewed. Two consecutive current runs were stable.

No silent stale baseline

An improvement fails normal CI until the explicit ratchet regenerates and commits the baseline.

Temptation to chase the score

This slice adds no behavioral tests. The next gap is selected by behavior risk from the trustworthy report.

No metric compensation

A gain in one metric or file cannot pay for a regression in another. Both ratchet invariants apply independently.

Resolved decision

Proceed with reporting and ratcheting first

Behavioral coverage increases, backend failure tests, and mutation testing remain follow-up work after this evidence layer is implemented and inspected.
