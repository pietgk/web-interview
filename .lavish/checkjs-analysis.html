A real bug was reproduced.

syncTodoListsRequestSchema refines the request object as if it were a transaction. Its early guard always returns, so a datom whose transaction ID differs from its envelope is accepted. A direct runtime probe returned { accepted: true }. Existing tests do not cover this invariant.

Decision

Recommended

Phased cleanup, then global enablement

  • Preserves editor feedback and adds a reliable CI gate.
  • Fixes schema and API boundary mistakes instead of hiding them.
  • Keeps JavaScript while documenting contracts with JSDoc and schema-derived types.
  • Lets each project turn green independently.
Not recommended

Flip the base flag and suppress errors

  • Immediately breaks every editor project except E2E.
  • Encourages broad @ts-ignore comments and weakens trust in the check.
  • Leaves third-party JavaScript noise mixed with product defects.
  • Makes the existing test suite look sufficient when the reproduced bug proves otherwise.

Add a root typecheck script that runs all four configs. Add the failing shared regression test for mismatched transaction IDs before changing the schema.

Clean the backend boundary

Install direct declaration packages, then type config/environment input, seed data, server actor options, Express handlers, and tests. Re-run after declarations because they may reveal more precise application errors.

Exit: backend typecheck, tests, and lint are green with no application or dependency JavaScript diagnostics.

Clean frontend production code, then tests

Type API options and errors, replica storage options, todo IDs, date calculations, React style objects, and component props. Finish with typed Vitest mocks and valid test fixtures.

Enable globally and enforce in CI

Exit: a clean checkout passes typecheck, tests, lint, build, and E2E checks.

Guardrails

  • Do not exclude production files or imported shared code to reduce the count.
  • Prefer schema-derived and shared JSDoc types at module boundaries over duplicating object shapes.
  • Keep skipLibCheck, but understand that it skips declaration-file checking, not untyped JavaScript in node_modules.
  • Declare frontend React types directly rather than relying on MUI or Testing Library to install them transitively.
  • Treat fixes that change runtime behavior, especially schema refinement, as bug fixes with focused tests.
